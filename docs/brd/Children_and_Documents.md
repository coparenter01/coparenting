## 2. Purpose and scope

**2.1 Purpose.** This module is one place for the practical information about the child and the documents both parents need. It holds the child list of the household, the child information (medical, school and contacts) and secure document storage. Later phases add a photo album, a wish list, shared tasks, expiring share links and an emergency contact.

**2.2 Objectives this module supports.** Objective IDs come from Common BRD section 2.3.

| ID     | How this module supports it                                                                                                                                                                                |
|--------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| OBJ-01 | Shared child information and shared documents are kept with their history and can be exported through Records and Court (DOC-01, DOC-02).                                                                  |
| OBJ-04 | Child information and document storage are in the free core plan, with storage limits that are clear (DOC-01, DOC-02).                                                                                     |
| OBJ-05 | Address, phone and email entered by a user in Safety Mode are hidden from the other parent. Photos lose their location data. The emergency contact is not offered in Safety Mode (DOC-01, DOC-03, DOC-07). |
| OBJ-06 | The web app has the full feature set. Photos and files can be added from a phone browser (DOC-02, DOC-03).                                                                                                 |

The Scope document links no pain point to this module. Related pain points are P24 (clear plan limits, DOC-02 storage) and P14 (Safety Mode, DOC-01 and DOC-03).

**2.3 In scope.** The seven features DOC-01 to DOC-07 listed in section 5.

**2.4 Out of scope for this BRD.** These items belong to another module or to a later decision.

## 3. Users and roles

Roles are defined in Common BRD 7.1 and the shared permission matrix is in Common BRD 7.2. The table shows what each role does in this module.

| Role                             | What they do in this module                                                                                                                                                                |
|----------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Parent                           | Adds and archives children, adds child information entries, uploads documents, shares items with the co-parent, and manages everything in Phase 3 features.                                |
| Co-parent                        | Once linked, adds child information entries, uploads documents and uses the Phase 3 features. Sees the child list. Cannot change a child record (Common BRD 7.2).                          |
| Third party                      | Sees the child information sections that the parents choose, view only. Access comes with ACC-07 in Phase 2. In Phase 3 a person outside the app can open a document through a share link. |
| Professional                     | Reads the child information and documents that a parent shares (Common BRD 7.2). Cannot post. Access comes with PRO-01, Phase 2.                                                           |
| Emergency contact                | A person a parent names in Phase 3. Has no account. Gets only the key notifications (DOC-07). This is a state of a person, not a role in Common BRD 7.1.                                   |
| Support staff and Platform admin | No feature in this module. Common BRD 7.2 gives them no access to household and children data or to documents.                                                                             |
| Child                            | No feature in this module. A child account is part of ACC-07.                                                                                                                              |
| Agency staff                     | Not users of the app (Scope document 4.2, decision 13).                                                                                                                                    |

Permissions for module data: Common BRD 7.2 gives the Parent CRUD and the Co-parent R on household and children, the Third party R (limited) and the Professional R (shared only). This module keeps that rule for the child record (name and date of birth). It needs a wider right for child information entries and documents, because both parents add them (decision Q-02). CR-01 asks to add the rows for child information entries and documents to Common BRD 7.2. A child record is archived and never deleted. A shared entry or document is archived and never deleted (decisions Q-01 and Q-05).
