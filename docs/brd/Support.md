## 2. Purpose and scope

**2.1 Purpose.** This module is the help side of the product. Slow or unhelpful support came up in reviews of the existing apps (P09). The module gives every request a case number, sets reply targets, puts issues tied to a court date first, and gives parents a searchable help center.

**2.2 Objectives this module supports.** Objective IDs come from Common BRD section 2.3.

| ID     | How this module supports it                                                                    |
|--------|------------------------------------------------------------------------------------------------|
| OBJ-03 | Fixes the pain point P09 (SUP-01). P09 is rated Medium, so it is not one of the 12 High items. |
| OBJ-04 | Handles fee waivers and refunds, so that cost is not a barrier (Billing BRD; SUP-02).          |
| OBJ-05 | Protects parents at risk: Safety requests are handled first and discreetly (SUP-01, SUP-02).   |

**2.3 In scope.** The feature SUP-01 listed in section 5, and the proposed features SUP-02 (the staff workspace) and SUP-03 (support measures). SUP-02 and SUP-03 are needed to run SUP-01 and to meet the Billing, Messaging and Child Support Sync BRDs (CR-01).

**2.4 Out of scope for this BRD.** These items belong to another module or to a later decision.

| Item                                                                                               | Where it belongs                                                                         |
|----------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------|
| The rules for waivers and refunds (who is eligible, the refund window, the decision targets)       | Billing and Plans (Billing BRD, decisions Q-08 and Q-09). This module handles the cases. |
| Sending alerts and emails                                                                          | Notifications (NTF). This module gives the events (CR-05).                               |
| The design of Safety Mode                                                                          | Safety and Privacy (SAF-01).                                                             |
| Phone support and live chat                                                                        | Not in the first release (decision Q-02).                                                |
| Weekend support hours                                                                              | Added only if the data shows a need (decision Q-15).                                     |
| Manual recovery of an account when a parent has lost access to the email and mobile number on file | Not in this BRD (decision Q-19).                                                         |
| Legal advice                                                                                       | Out of scope (Scope document 4.2). Support gives record tools and model language only.   |
| Support in languages other than English                                                            | Spanish comes with ACC-08 in Phase 2 (Accounts BRD, decision Q-01).                      |
| Agency staff as users                                                                              | Out of scope for now (Scope document decision 13).                                       |

**2.5 Release phases of this module.** The Scope document puts SUP-01 in Phase 2. This BRD moves SUP-01 and SUP-02 to the MVP (web), because the MVP launches with the checkout and refunds (Billing BRD, decision Q-02) and Scope decision 26 says to launch with email and an in-app form (decision Q-01, CR-01). SUP-03 is in Phase 2 (web). The phase of each feature is a proposal (Scope document 4.4).

## 3. Users and roles

Roles are defined in Common BRD 7.1 and the shared permission matrix is in Common BRD 7.2. The table shows what each role does in this module.

| Role                                | What they do in this module                                                                                                                                                                                 |
|-------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Parent                              | Searches the help center, opens a request, follows the case, replies, reopens a case and answers whether the problem was solved.                                                                            |
| Co-parent                           | The same as the Parent, for their own requests.                                                                                                                                                             |
| Support staff                       | Works the queue, replies to parents, handles waiver and refund cases, and posts service notices. They have two levels, Agent and Lead (decision Q-10, CR-03). Cannot read parent messages (Common BRD 7.1). |
| Platform admin                      | No feature in this module.                                                                                                                                                                                  |
| Professional, Third party and Child | Can open a request when signed in (decision Q-17). No other feature.                                                                                                                                        |
| A person who cannot sign in         | Can open a request from the sign-in page and read the help center (decision Q-05).                                                                                                                          |

Permissions for module data: Common BRD 7.2 gives the Parent R (own) on waivers and refunds, and the Support staff CRU. A parent and a support staff member need rights on support cases, help articles and service notices. These are new rows (CR-03). A parent can create and read their own cases. A support staff member can read every case and reply. Only a Lead can create or change help articles, reply templates and service notices, and only a Lead can see a message that a parent shared with consent (decision Q-10).
