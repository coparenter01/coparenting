## 2. Purpose and scope

**2.1 Purpose.** This module takes a parent from sign-up to a working account and gets the co-parent on board. If the co-parent will not join, the parent can carry on alone and still keep a proper record.

**2.2 Objectives this module supports.** Objective IDs come from Common BRD section 2.3.

| ID     | How this module supports it                                                                                                               |
|--------|-------------------------------------------------------------------------------------------------------------------------------------------|
| OBJ-01 | The contact-attempt log is part of the court-ready record (ACC-05).                                                                       |
| OBJ-02 | Sign-in strength is needed because the app holds agency data (ACC-01). An agency notice can later carry an invite (CSS-09, Sync phase 2). |
| OBJ-03 | Fixes the High-rated pain point P11 in the first release (ACC-02 to ACC-05).                                                              |
| OBJ-04 | No billing starts until the co-parent is linked or the parent chooses Solo Mode (BR-03).                                                  |

**2.3 In scope.** The twelve features ACC-01 to ACC-12 listed in section 5. ACC-09 to ACC-12 are proposed additions (CR-01 in section 15.3).

**2.4 Out of scope for this BRD.** These items belong to another module or to a later decision.

| Item                                                       | Where it belongs                                                             |
|------------------------------------------------------------|------------------------------------------------------------------------------|
| Charging and plans                                         | Billing and Plans (BIL). This module only records the household mode.        |
| Sending text and email                                     | Notifications (NTF).                                                         |
| Export of the contact-attempt log                          | Records and Court (REC).                                                     |
| Linking a child support case and the agency identity check | Child Support Sync, CSS-01.                                                  |
| Agency notice as an invite channel                         | CSS-09, Sync phase 2.                                                        |
| Invites and read-only access for professionals             | Professionals and Access (PRO). It needs invites and roles from this module. |
| Group chat and messages to third parties                   | MSG-10, Phase 3.                                                             |
| Emergency contact assignment                               | DOC-07, Phase 3.                                                             |
| Languages other than English and Spanish                   | Out of scope for now (Scope document 4.2).                                   |
| Agency staff as users                                      | Out of scope for now (Scope document 4.2, decision 13).                      |
| Biometric lock                                             | Deferred. Not needed now (decision Q-03). The passcode lock stays in ACC-01. |
| Spanish in the first release                               | Not in the MVP. Spanish is in Phase 2 (decision Q-01).                       |

**2.5 Release phases of this module.** MVP (web): ACC-01 to ACC-05 and ACC-09 to ACC-11. Phase 2 (web): ACC-06 to ACC-08 and ACC-12. The phase of each feature is a proposal (Scope document 4.4).

## 3. Users and roles

Roles are defined in Common BRD 7.1 and the shared permission matrix is in Common BRD 7.2. The table shows what each role does in this module.

| Role                             | What they do in this module                                                                                                                                                                                                                                             |
|----------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Parent                           | Creates an account, signs in with two-factor sign-in, turns on the app lock, invites the co-parent, chooses Solo Mode, contacts a co-parent who is not on the app, and views the contact-attempt log. In Phase 2: sets the session timeout and manages household roles. |
| Co-parent                        | Receives an invite. After accepting, creates an account and signs in with two-factor sign-in like every user.                                                                                                                                                           |
| Co-parent who is not on the app  | Receives a text or email from the parent (ACC-04). Has no account. This is a state of a person, not a role in Common BRD 7.1.                                                                                                                                           |
| Third party                      | Phase 2. Added by a parent. Sees what the parents allow (ACC-07).                                                                                                                                                                                                       |
| Child                            | Phase 2. A limited account where the parents allow it. Messages and calendar view only, as set by the parents (ACC-07).                                                                                                                                                 |
| Support staff and Platform admin | No feature in this module. Common BRD 7.2 gives both read access to own-profile data and the audit log.                                                                                                                                                                 |
| Professional                     | Not covered here. Invites and roles for professionals are in PRO.                                                                                                                                                                                                       |

Permissions for module data: a parent can create and read their own invites and their own contact-attempt log. No role can edit or delete a contact-attempt entry (NFR-05). Support staff cannot read parent messages (Common BRD 7.1), so they cannot read the exchange with a co-parent who is not on the app. No other role can see the invite list, the contact-attempt log or the exchange with a co-parent who is not on the app, unless the parent shares them with a professional or selects them for an export (decision Q-11).
