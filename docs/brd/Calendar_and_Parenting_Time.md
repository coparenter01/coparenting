## 2. Purpose and scope

**2.1 Purpose.** This module holds the custody schedule and everything that changes it. It gives both parents the same view of who has the child and when.

**2.2 Objectives this module supports.** Objective IDs come from Common BRD section 2.3.

| ID     | How this module supports it                                                                                                      |
|--------|----------------------------------------------------------------------------------------------------------------------------------|
| OBJ-01 | Requests, approvals and the history of every entry are part of the court-ready record (CAL-02, CAL-10).                          |
| OBJ-02 | Hearings and deadlines from the agency record appear in the calendar (CAL-01). Sync phase 1 needs CAL-01 from the first release. |
| OBJ-03 | Fixes the High-rated pain point P06 in the first release (CAL-02, CAL-10).                                                       |
| OBJ-05 | Event locations and check-ins follow Safety Mode (CAL-01, CAL-09).                                                               |

**2.3 In scope.** The eleven features CAL-01 to CAL-11 listed in section 5.

**2.4 Out of scope for this BRD.** These items belong to another module or to a later decision.

| Item                                                             | Where it belongs                                                                                          |
|------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------|
| Sending reminders and alerts                                     | Notifications (NTF-01, NTF-04, NTF-06). This module gives the times and changes.                          |
| The case link and the agency data                                | Child Support Sync (CSS). This module shows the hearings, deadlines and due dates.                        |
| The design of Safety Mode                                        | Safety and Privacy (SAF-01).                                                                              |
| The export format of calendar records                            | Records and Court (REC).                                                                                  |
| Pet expenses and other expenses                                  | Expenses and Payments (EXP).                                                                              |
| Accounts for a Third party or a Child                            | Accounts and Onboarding (ACC-07, Phase 2).                                                                |
| Paid plan rules for calendar sync and parenting-time reports     | Billing and Plans (Billing BRD, decision Q-01).                                                           |
| Discussion about a request                                       | Messaging (MSG).                                                                                          |
| Sending events and requests to a co-parent who is not on the app | Not in this BRD. The Accounts BRD sends messages to that person (ACC-04).                                 |
| Legal advice                                                     | Out of scope (Scope document 4.2). The parenting plan builder gives record tools and model language only. |

**2.5 Release phases of this module.** MVP (web): CAL-01, CAL-02 and CAL-10. Phase 2 (web): CAL-03, CAL-04, CAL-05 and CAL-06. Phase 3 (later): CAL-07, CAL-08, CAL-09 and CAL-11. CAL-10 moves from Phase 2 to the MVP (decision Q-11, CR-01). The phase of each other feature is a proposal (Scope document 4.4).

## 3. Users and roles

Roles are defined in Common BRD 7.1 and the shared permission matrix is in Common BRD 7.2. The table shows what each role does in this module.

| Role                             | What they do in this module                                                                                                        |
|----------------------------------|------------------------------------------------------------------------------------------------------------------------------------|
| Parent                           | Adds events and parenting time, sends and answers schedule change requests, builds schedules, tracks parenting time and checks in. |
| Co-parent                        | The same as the Parent, once linked.                                                                                               |
| Third party                      | Sees the parts of the calendar the parents allow, view only (Phase 2, ACC-07).                                                     |
| Child                            | Views the calendar as the parents allow (Phase 2, ACC-07).                                                                         |
| Professional                     | Reads the calendar entries and reports that a parent shares (Common BRD 7.2). Cannot post.                                         |
| Support staff and Platform admin | No feature in this module.                                                                                                         |

Permissions for module data: Common BRD 7.2 gives the Parent and the Co-parent CRU and the Third party R (as set) on calendar events. It has no delete right, so this module cancels entries and never deletes them (decision Q-12). Parents also create and answer schedule change requests, and nobody can change a request after it is answered.
