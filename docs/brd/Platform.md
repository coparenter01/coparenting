## 2. Purpose and scope

**2.1 Purpose.** This module sets how the app is delivered. The plan is a web app first, then mobile apps on the same core. Several apps in the review have no web app (P26). This module also holds the rules that every other module relies on: browsers, speed, availability, backup, accessibility and the security baseline.

**2.2 Objectives this module supports.** Objective IDs come from Common BRD section 2.3.

| ID     | How this module supports it                                                                                                                       |
|--------|---------------------------------------------------------------------------------------------------------------------------------------------------|
| OBJ-03 | Fixes the pain point P26 (PLT-01, PLT-02, PLT-03). P26 is rated Medium, so it is not one of the 12 High items.                                    |
| OBJ-04 | A web app needs no download and no store fee, which keeps the cost low (PLT-01).                                                                  |
| OBJ-05 | The security baseline, the privacy rules for analytics and cookies, and the accessibility rules protect parents and build trust (PLT-05, PLT-06). |
| OBJ-06 | This objective is the module: build the web app first, then mobile on the same core (PLT-01, PLT-02).                                             |

**2.3 In scope.** The three features PLT-01 to PLT-03 listed in section 5, and the proposed features PLT-04 (service reliability), PLT-05 (accessibility) and PLT-06 (security and privacy baseline). PLT-04 to PLT-06 close the open non-functional items of Common BRD section 10 and the gaps that the other module BRDs rely on (CR-01).

**2.4 Out of scope for this BRD.** These items belong to another module or to a later decision.

| Item                                                                    | Where it belongs                                                                        |
|-------------------------------------------------------------------------|-----------------------------------------------------------------------------------------|
| Sign-in, two-factor checks, passwords and session rules                 | Accounts and Onboarding (ACC). This module sets the platform side only.                 |
| Alerts, push and delivery rules                                         | Notifications (NTF). This module gives the web and mobile channels.                     |
| Plans, prices and checkout                                              | Billing and Plans (BIL). The apps open the web checkout (decision Q-10).                |
| The design of Safety Mode and the quick exit                            | Safety and Privacy (SAF-01). This module gives the neutral titles and the neutral icon. |
| A desktop app, a smart watch app and a tablet layout beyond the web app | Not planned.                                                                            |
| Languages other than English and Spanish                                | Out of scope for now (Scope document 4.2).                                              |
| Connecting to a state system                                            | Child Support Sync (CSS).                                                               |
| Choosing the hosting provider, the framework and the tools              | IT (decisions Q-05 and Q-12). This BRD sets the rules they must meet.                   |

**2.5 Release phases of this module.** MVP (web): PLT-01, PLT-03, PLT-04, PLT-05 and PLT-06. Mobile phase: PLT-02. The mobile phase starts when the web MVP has been live for 60 days with no open critical defect and phone browser use shows demand (Scope document decision 29, decision Q-06). The phase of each feature is a proposal (Scope document 4.4).
